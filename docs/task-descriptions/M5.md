# M5 — Scheduling and Administrator Operations

**Purpose:** Give administrators the operational tools to search, schedule, assign, and audit collections.

**Task count:** 9

**Status:** Complete — implemented and verified on native PostgreSQL.

## M5 implementation evidence

- Migration: `V5__administrator_operations.sql`; backend: `operations/OperationsService` and `OperationsController`, with transactional collector provisioning and request cancellation.
- UI: `features/admin/AdminOperations.tsx`, shared admin navigation, existing M4 grouping view, and administrator login routing to `/admin`.
- Workflow and authorization: `OperationsIntegrationTests`; real overlapping transaction protection: `AssignmentConcurrencyTests`; M0–M4 regression tests remain green.
- Frontend: page loading, scheduling, conflicts, search/pagination, settings, request details, and retry tests in `AdminOperations.test.tsx`; lint, TypeScript production compilation, and build pass.
- Live localhost: administrator reads for dashboard, requests, collections, collectors, audit, and settings return HTTP 200; resident login remains available.
- Scheduling policy, cancellation reconciliation, assignment history, bounded settings/search, duplicate behavior, and later M6 work are documented in the API contracts, business rules, database design, frontend plan, and test plan.
- Verification on 2026-10-09: `mvn verify` passed 15 backend tests; frontend lint, 17 component tests, TypeScript production compilation, and Vite build passed. Both localhost services are running with V5 applied.
